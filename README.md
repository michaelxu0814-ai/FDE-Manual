# 驻场手册 — FDE 三月纲要

完整设计版（带排版）：https://claude.ai/code/artifact/bc6e384e-4c69-4b40-9043-1baa80085681

## 目标画像

AI 应用落地方向的 Forward Deployed Engineer —— 技术是手段，解决客户问题是目的。

- **起点**：零代码基础；有全盘运营背景（电商 / 零售 / 采购），已习惯用 AI 辅助学习
- **周期**：3 个月，按 12 周计
- **每日预算**：全天穿插的轻量闪卡推送 + 每天 1 小时深度实操
- **成功标准**：接到一个新客户需求时，不靠人手把手指导，也能按固定方法论走完摸底到交付，拿出经得起检验的成果

## 核心方法论 · 五步循环

1. **摸底 Discovery** — 把客户模糊的诉求变成可验证的问题。产出：一页需求纪要。
2. **判断 Architecture** — 决定用什么办法、为什么。产出：一页架构说明。
3. **搭建 Build** — 用固定技术骨架把方案跑出来。产出：能跑起来的最小版本。
4. **验收 Harden** — 让它经得起用。产出：测试记录 + 已知问题清单。
5. **交付 Deliver** — 让客户能用、能听懂为什么。产出：可访问的部署 + 交付说明。

这五步在三段模拟客户里各完整走一遍，一次比一次少人扶着走。

## 技术骨架（3 个月内固定）

| 角色 | 选择 | 为什么 |
|---|---|---|
| 主力语言 | Python | AI 生态最成熟，AI 编程助手对它最熟练 |
| 大模型接入 | Claude API | 理解"调用"和"给工具用"背后发生了什么 |
| 数据层 | SQLite + Pandas | 企业数据落地最常见的轻量组合 |
| 界面层 | Streamlit | 最快把逻辑变成客户能点开用的东西 |
| 部署 | Railway / Vercel | 交付是别人能访问到，不是本地能跑 |
| 版本管理 | Git / GitHub | 专业交付最起码的可追溯性 |
| 主力工具 | Claude Code | 带着 AI 副驾驶做交付，现在真实的 FDE 工作方式 |

## 三段模拟客户

| Phase | 周数 | 场景 | 重点 |
|---|---|---|---|
| 01 起步 | Week 1–4 | 电商客服助手（RAG 入门） | 环境、API 调用、检索增强基础、界面、部署 |
| 02 接手 | Week 5–9 | 运营自动化流程（订单异常 + 日报） | 工具调用、多步骤 agent、结构化数据、错误处理 |
| 03 独立 | Week 10–12 | 开放式命题（模拟需求访谈） | 全流程独立主导，企业级交付标准验收 |

各 Phase 详细场景与完成标准见 Artifact 或 phase-0X/ 目录。

## 每日节奏

- **闪卡推送**（全天穿插，Telegram）：针对当前知识点做主动回忆测试，轻量，可调
- **深度 Session**（每天 1 小时）：当前 Phase 项目的实际动手
- **每周五**：小复盘，自测本周知识点
