# Phase 01 · Week 3 — 把助手变成"客户能点开用"的东西（Streamlit 界面）

场景延续：客服助手的"脑子"（RAG）Week 2 已经能跑了，但它是命令行里的东西——客户不可能
打开终端敲命令。Week 3 的目标：做一个网页界面，客户打开一个链接就能提问、就能看到回答。

每天 1 小时。做不完没关系，宁可少而扎实，也不要囫囵吞枣往下赶。

## Day 1 — 认识 Streamlit：三行代码出页面

**目标**：装好 Streamlit，本地跑出一个最简页面。

- 在 Week 2 的虚拟环境里装 `streamlit`，写一个最小的 `app.py`：一个标题 + 一个按钮。
- 用 `streamlit run app.py` 跑起来，浏览器里看到你的页面。
- 概念：Streamlit 是"把 Python 逻辑变成网页界面"的工具，不用学 HTML/JS，专注逻辑本身。
- 让 Claude Code 带你读 `app.py`，搞清楚"每一行对应页面上什么"。

**今天不需要懂**：怎么把页面放到公网。那是 Week 4。今天只要本机浏览器能看到。

## Day 2 — 把 Week 2 的 RAG 逻辑接进页面

**目标**：客户在页面里输入问题，点按钮，看到回答。

- 页面加：一个输入框（客户提问）、一个按钮（提交）、一块展示区（显示回答）。
- 把 Week 2 的"检索 + 调用模型"逻辑接进去：点按钮 → 跑检索 → 出回答。
- 概念：前端和后端不需要分开，一个 `app.py` 全搞定（MVP 阶段）。

## Day 3 — 显示出处 + 处理"乱输入"

**目标**：回答旁边能看到它引用的手册片段；乱输入不崩。

- 把检索到的相关片段展示在回答下方（"参考依据"），客户能自己查证。
- 处理边界：空输入给提示、输入手册外的问题模型要老实说不知道、提交按钮防重复点击。
- 概念：**"能跑"≠"像样"**。边界处理是"敢交给客户"的分水岭。

## Day 4 — 打磨：让页面"像个客服工具"

**目标**：标题、提示语、加载状态、历史对话都到位。

- 加标题/说明文字（"客服助手——请用一句话描述您的问题"）。
- 显示历史对话（客户问过什么、答过什么），用 `session_state` 记住，页面刷新不丢。
- 加"正在思考…"的加载状态，客户等待时不慌。
- 自测：把自己当客户，完整走一遍，找出所有"尴尬"的点。
