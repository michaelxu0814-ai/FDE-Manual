# 本地项目的 CLAUDE.md 模板

## 这是什么

`CLAUDE.md` 是放在项目文件夹根目录的一个文件。Claude Code 每次在那个项目里工作时，
会自动读它，把里面写的规矩当作固定要求执行——**不需要你每次重新叮嘱一遍**。

这就是"约定"从口头变成机制的办法：写进 CLAUDE.md 的规矩会自动生效，说在聊天里的
话下次开新会话就忘了。

## 怎么用

在你的项目文件夹（比如 `fde-week1`）里建一个叫 `CLAUDE.md` 的文件，把下面分割线之间
的内容整个复制进去。以后每个新项目都放一份。

一句话让 Claude Code 帮你建：

> "在当前项目根目录建一个 CLAUDE.md，内容我贴给你。"

---

```markdown
# 项目约定

这是一个学习项目。用户零代码基础，正在通过实操学习 AI 应用落地。
教学效果优先于完成速度——把事情做完但用户没搞懂，等于没做。

## 装任何新包之前，必须先过卡

执行 `pip install` 之前先停下，给出这张卡，等我确认后再装：

- 包名：
- 它是什么、这次为什么要装：
- 谁维护的：官方组织 / 知名开源项目 / 个人项目 / 不确定
- 判断依据：来自官方文档，还是你的既有知识？（必须说清是哪一种）
- 风险等级：低 / 中 / 高
- 会连带装进来哪些依赖：

风险等级是"中"或"高"时，不许只凭记忆判断，要实际去查 pypi.org 上的维护者和发布历史，
把查到的结果给我看。

不要在同一步里既给卡又把包装了——必须等我点头。

## 密钥安全

- 绝不把 API key 明文写进代码文件
- 写进 `.env` 之前，先确认 `.gitignore` 里已经有 `.env`，顺序不能反
- 每次 `git add` / `git commit` 前，检查这次要提交的文件里有没有密钥模样的字符串
- 不需要知道我的 key 的值，只需要知道它存在环境变量里

## 执行前先解释

任何命令，执行前先用大白话说清楚：这一步在做什么、为什么需要这一步。
不要一口气跑完再统一解释——我需要跟得上每一步，而不是最后拿到一个能跑的结果。

## 收尾时给延展

每次做完一个知识点，主动告诉我周围的地图：同类的工具还有什么、上下游是什么、
真实工作里什么时候会碰到、以及**哪些现在不用管**。
我处在"不知道自己不知道什么"的阶段，靠我提问补不全盲区。
```

---

## 注意

这份模板跟仓库根目录的 `CONVENTIONS.md` 是同一套规矩的两个副本：
- `CONVENTIONS.md` —— 完整版，讲清楚每条规矩的来由和后果，是给人读的
- 本模板 —— 压缩版，是给 Claude Code 读的执行指令

改了一边，记得同步另一边。
